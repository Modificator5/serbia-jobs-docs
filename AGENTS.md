# AGENTS.md — Конституция проекта «Сербия: работа для русскоязычных»

Это **единственный источник правил** для любого «мозга» (OpenCode, Claude, ChatGPT,
Gemini, другой агент). Прочитай этот файл целиком перед первой задачей.
Остальные docs — данные и история; при противоречии с этим файлом побеждает этот файл.

## 1. Суть проекта

1. Парсим площадки вакансий Сербии → короткие карточки в одну SQLite-базу `data/jobs.db`.
2. **Перевод один раз, а не каждый раз**: уникальный `title_sr` переводится один раз
   в таблицу `professions` и переиспользуется всеми вакансиями. Потерять `title_ru`
   при upsert/cleanup = сломать всю экономику проекта.
3. Словарь — половина продукта: личная база `docs/glossary/bazaznanja.txt` +
   термины из вакансий → таблицы `glossary`/`job_words` (ссылка на реальную вакансию).
4. Витрина: локальный сайт (`npm run viewer`), затем Telegram-канал.
   Без публикации парсинг бессмыслен.

## 2. Стартовый чеклист (обязателен перед любой задачей)

```bash
git status --short --branch          # ожидаем чистое дерево
git diff --cached                    # перед стейджем должен быть пуст
git remote -v                        # origin = приватный; mirror НЕ трогаем без задачи
git ls-files | grep -E '^(data/|logs/|snapshots/|jobs\.json$)'   # должен пустой вывод
node tools/memory.js search "<ключевые слова задачи>"            # память: что уже делали
npm run verify                       # doctor + tests + docs:check
```

Если чеклист не прошёл — остановись и сообщи пользователю, не генерируй решение вслепую.

## 3. Память и теги (жёсткое правило экономии токенов)

Перед тем как сгенерировать ответ, решить задачу или позвать воркера — **найди
существующий опыт**:

1. `memory/tasks.jsonl` — журнал задач проекта с тегами:
   - `SOLVED` — задача решена (что сделать: ссылка/файл/коммит),
   - `TRIED` — пытались, не сработало (что пробовали и почему не подходит),
   - `REJECTED` — осознанно отказались (обоснование),
   - `PENDING` — в очереди.
2. `logs/ask-journal.md` — что уже спрашивали у воркеров (не задавай вопрос повторно;
   при повторе опирайся на прежний ответ или уточняй, а не генерируй заново).
3. `.ai_memory/*.jsonl` — кеш ответов провайдеров (хеш промпта): при совпадении
   провайдер вернёт готовый ответ без запроса в сеть.

Правила записи в память:
- Каждая завершённая/отклонённая/проваленная задача → одна строка в
  `memory/tasks.jsonl` тем же коммитом (или сразу после решения).
- Формат одной строки (JSON): `{"date": "YYYY-MM-DD", "task": "...", "status":
  "SOLVED|TRIED|REJECTED|PENDING", "tags": ["..."], "refs": ["path:line|URL|коммит"]}`.
- Память — это не дневник, а индекс: коротко, с ключевыми словами для поиска.
- Теги задач дублируются в `docs/decisions.md`, если решение меняет архитектуру.

Поиск перед генерацией: `node tools/memory.js search "термин" [тег]`
(`memory.js` сам читает `memory/tasks.jsonl`, при отсутствии файла — тихо ничего не делает).

## 4. Git: что и как коммитить

- **Никогда** `git add -A` / `git add .`. Только явные пути.
- В git входят: код, docs, prompts, конфиги, `memory/`.
- В git **не входят**: `data/`, `logs/`, `snapshots/`, `jobs.json`, `.env`,
  `.ai_memory/`. Генерируемые артефакты коммитить запрещено.
- `origin` — приватный основной репозиторий. Remote `mirror` (публичное зеркало
  `serbia-jobs-docs`) пушить только по явной задаче пользователя.
- Коммит после каждой завершённой задачи; в сообщении — что и почему.
- Если задача меняет структуру или архитектуру — в том же коммите обнови
  `docs/architecture.md` и добавь запись в `docs/decisions.md`.

## 5. Токен-экономия (жёсткие лимиты)

- Сырой HTML в LLM не отправлять — только статистика и примеры.
- Максимум **2 вызова воркеров** на нетривиальную задачу (для неё нужен второй
  взгляд); рутина — один локальный провайдер.
- Переводы/батчи — `ollama` (локально); анализ — `gemini`; fallback — `openrouter`.
- Сначала кеш `.ai_memory/` и `memory/tasks.jsonl` → потом воркер.
- Парсеры: дефолты страниц маленькие (KP 5, Infostud 2), паузы не уменьшать.
- Тесты и бэктесты — по CSV/фикстурам, не по сети.
- Ответы воркеров журналируются обрезанными (≤6000 символов).

## 6. Мультиагенты

| Ключ | Назначение | Кто | Файл инструкции |
|---|---|---|---|
| `ROUTINE_LOCAL` | переводы, батчи, форматирование | Ollama (локально) | `prompts/worker-routine.md` |
| `CODE_FAST` | синтаксис, рефакторинг, ревью | Groq / Llama | `prompts/worker-coder.md` |
| `LOGIC_CORE` | архитектура, глубокий анализ, спорные решения | Gemini (+ второй воркер на консенсус) | `prompts/worker-logic.md` |

Все вызовы через `tools/ask.py <провайдер> <промпт>` (кеш + fallback + журнал
с ротацией > 1 МБ). Запрос = `prompts/worker-core.md` + один ролевой файл.
Стандарт ответа воркера-рутины — JSON-конверт `{"status":"success","data":...}`
(нормализуется в `tools/ai.js`). Нарушение формата = синтаксическая ошибка:
один повтор, затем fallback. Внешний ответ пользователю — 4 блока
`[Сравнение] [Вердикт] [Результат] [Действие]` (`prompts/lead-engineer.md`).
Мозг (OpenCode/внешний ИИ) синтезирует и принимает решение — код пишет только тот,
у кого есть доступ к файлам. Протокол: `docs/agents.md`.

## 7. Definition of Done задачи

1. Код работает и не ломает пайплайн (направление: скрейп → translate → enrich → export).
2. `npm run verify` зелёный (doctor + tests + docs:check).
3. Доки обновлены в том же коммите (затронутые + `docs/progress.md`).
4. Память обновлена: строка в `memory/tasks.jsonl` (тег `SOLVED`/`TRIED`/`REJECTED`).
5. Git: чистое дерево, явные пути, артефакты не закоммичены.

## 8. Карта проекта

- `scrapers/` — парсеры (по одному на площадку) + `common.js`, `db.js`
- `tools/` — экспорт, перевод, обогащение, очистка, Telegram, `ask.py`, `memory.js`,
  `doctor.js`, `docs-check.js`
- `tests/` — офлайн-тесты парсеров на фикстурах (`parsers.test.js`)
- `viewer/server.js` + `index.html` — локальный сайт (127.0.0.1:7788)
- `docs/` — канонические документы (см. `docs/README.md`)
- `prompts/` — инструкции: `lead-engineer.md`, `worker-core.md` + ролевые
  (`worker-logic.md`, `worker-coder.md`, `worker-routine.md`)
- `memory/tasks.jsonl` — индекс задач с тегами (память)
- `logs/` — журналы (локально, в git не входят)
- `data/jobs.db` — единственный источник правды по вакансиям (локально)
- `.github/workflows/verify.yml` — CI: `npm run verify` на push/PR

Полезное: `README.md` (команды), `docs/README.md` (индекс документов),
`docs/progress.md` (текущее состояние), `SYSTEM.md` (регламент).
