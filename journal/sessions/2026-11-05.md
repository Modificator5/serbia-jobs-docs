# 2026-11-05 — проверяемая публикация, живой словарь, журнал

## Сделано

- Публикация в Telegram берёт только новые вакансии (`is_published = 0`,
  есть `title_ru`, дедуп по `title_sr|city|company_short`). `--all` означает
  «все подходящие неопубликованные», а не всю базу.
- Облачный ежедневный цикл GitHub Actions проверен: dry-run собрал 239
  вакансий, реальный запуск опубликовал 228 из 228.
- Исправлены Groq/OpenRouter: браузерный User-Agent, модель
  `openai/gpt-oss-120b`, пауза между пачками.
- Создана сквозная инструкция `docs/manual.md`.

## Решения

- Сырые логи и `.ai_memory/` в git не идут. В git едет только
  `journal/events.jsonl` и `memory/tasks.jsonl`.
- `data/jobs.db` в git не коммитится. В облаке она живёт в cache GitHub
  Actions, плюс сохраняется артефактом для восстановления.
- Словарь пополняется из полного текста вакансий, а не только из заголовков.
  `docs/glossary/bazaznanja.txt` — ручной seed, БД — рабочая истина.
- Полный текст вакансии хранится в `jobs.description`; парсеры тянут
  детальную страницу, а `tools/fetch-descriptions.js` добирает пропуски.
