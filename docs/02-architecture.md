# Архитектура

```
Площадки (Infostud, KP, Jooble...)
        │
        ▼
   scrapers/         парсеры, раз в сутки
        │  сырые данные → data/raw/ (временно)
        ▼
   нормализация      короткая карточка вакансии
        │
        ▼
   data/jobs.db      только ключевые поля, без простыней
        │
        ├──► glossary extraction → data/glossary.db
        │         (сербские слова/фразы, перевод, статус)
        │
        ▼
   api/              тонкий слой чтения (для бота и сайта)
        │
        ▼
   bot/              Telegram-канал → позже бот с подписками
```

## Принципы

1. **Сырой текст живёт временно.** Из вакансии вытаскиваем поля и слова для глоссария, затем raw удаляем/архивируем.
2. **Одна база на задачу.** jobs.db — вакансии. glossary.db — словарь. Связь через source_url и term_sr.
3. **Канал раньше бота.** Публикация витрины проще, чем подписки; бот добавляется вторым шагом поверх api/.
4. **Профессии переводятся единообразно.** Отдельная таблица professions (title_sr → title_ru), а не свободный перевод каждый раз.
5. **Парсеры изолированы.** Каждая площадка — свой модуль в scrapers/, общий интерфейс: `fetch() → [raw_listing]`.

## Стек

- Node.js (уже стоит под kanban) или Python для парсеров — решаем при первой задаче парсера.
- SQLite (better-sqlite3 или python sqlite3).
- Telegram Bot API для канала.
- Ollama для локальных переводов.
