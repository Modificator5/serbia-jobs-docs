### 1.1 `tools/backup-db.js` (new)

- Usage: `node tools/backup-db.js [keep=14]`
- Arguments: `keep` is an integer ≥ 1; anything else exits 2.
- Environment: `JOBS_DB` (default `data/jobs.db`), `BACKUP_DIR` (default `snapshots/backups`).
- Behavior: opens the DB read-only, runs `VACUUM INTO` a `.tmp` file, opens the copy and checks `PRAGMA integrity_check`, then renames to `jobs-YYYY-MM-DD.db` (UTC date). One backup per day; a rerun the same day overwrites it. Keeps the `keep` newest files matching `jobs-YYYY-MM-DD.db`, removes the rest.
- Output: `Backup: <path> (jobs=N, professions=M)`, then `Removed old backup: <file>` lines.
- Exit codes: 0 success; 1 DB missing or backup/integrity failure (temp file removed); 2 bad argument.
- Contains all tables, including `professions`, `glossary`, `job_words`.
- Why `VACUUM INTO`: the DB is in WAL mode, so copying `jobs.db` alone can miss recent writes that sit in `jobs.db-wal`.

### 1.2 `tools/cleanup.js` (modified)

- Usage: `node tools/cleanup.js [days=30] [--dry] [--force]`
- Environment: `JOBS_DB`.
- Rules, in order:
  1. Prints a per-source table: total, stale, last sighting (`MAX(substr(parsed_at,1,10))`).
  2. A source whose last sighting is older than the cutoff is "stalled" and is skipped entirely; a warning names it.
  3. If jobs to delete exceed 50% of all jobs and `--force` is absent, it refuses (exit 1). The refusal also applies to `--dry`.
  4. `--dry` prints the plan and deletes nothing.
  5. Otherwise deletes `job_words` rows first, then `jobs` rows, in one transaction, only for healthy sources.
- Exit codes: 0 done, nothing to delete, or dry run; 1 DB missing or refusal; 2 bad `days`.
- Unchanged: cutoff uses `parsed_at` (the last-seen timestamp), never `posted_at`.

### T1 — Redesign the ask layer (roles, journal, search)

Why: the code hard-codes five providers and a fixed fallback chain, the journal has no tags, search is exact-hash only, and the cache stores unvalidated answers. The user's intent: the brain addresses a capability role; configuration decides which model serves it; every exchange is logged with tags so repeated questions are found instead of re-asked. Workers and the brain both consult the log first.

Design requirements:
1. **Roles, not models.** The brain and AGENTS.md mention only `ROUTINE_LOCAL`, `CODE_FAST`, `LOGIC_CORE`. A config file (for example `config/providers.json`, no secrets) maps each role to an ordered list of provider entries: `{ "name", "base_url", "model", "api_key_env", "format" }`. API keys stay in `.env`. Model names appear only in this config and in journal records.
2. **One adapter for OpenAI-compatible endpoints** (OpenRouter, Groq, Ollama `/v1`, Gemini's OpenAI-compatible endpoint), plus a separate adapter for Anthropic's native format. Adding a provider means adding a config entry.
3. **Journal as JSONL** (`logs/ask-journal.jsonl`, rotated above 1 MB like today). Record fields: `ts`, `role`, `provider`, `model_requested`, `model_reported` (taken from the API response when it contains one), `origin` (`worker` or `user`), `tags` (automatic: role, script, provider; manual: topic via `--tags`), `volatile` (boolean or expiry date), `prompt_hash`, `prompt` and `answer` truncated to 6000 characters, `outcome` (`accepted`, `fallback`, `rejected`), `retries`.
4. **Search before asking, three levels:** (a) exact hash (exists); (b) tags plus tokenized words over the journal and `memory/tasks.jsonl`; (c) optional later: embeddings from a local model. `node tools/memory.js search` covers journal and tasks and prints date, source, and record number. Skip entries whose `volatile` expiry passed.
5. **Context injection with a budget.** When the brain delegates, it may add up to three matching past exchanges to the worker prompt, summarized and capped in size. Whole logs never go into prompts.
6. **Cache only valid answers.** Validate the expected format (JSON envelope for routine roles) before writing to `.ai_memory/`. Provide a bypass flag for repeating a call without cache. Never cache an empty or malformed answer.
7. **Format violation handling as AGENTS.md states:** one retry, then the next provider for the same role.
8. **No silent leave-the-machine fallback.** `ROUTINE_LOCAL` falls back only to entries in its own role list. Moving to an external provider requires an explicit `--allow-external` flag (see Q3).
9. **Timeouts:** the caller's timeout must cover the worst case of the adapter's retries, or the adapter must expose a total deadline.
10. **Prompt assembly:** documents first inside `<documents>`, task and question last; output format described in words with one example; no assistant prefill.
11. **Cache rotation:** cap `.ai_memory/*.jsonl` (for example 5 MB per file, archive the oldest half) and drop `volatile` entries after expiry.

Files affected: `tools/ask.py`, `tools/ai.js`, `tools/memory.js`, `config/providers.json` (new), `prompts/worker-core.md` plus role files if the output contract wording changes, `docs/agents.md`, `docs/architecture.md`, `docs/decisions.md`, `AGENTS.md`.

AGENTS.md update at the end of T1: in section 5 replace provider names with roles; in section 6 replace the table's "Who" column with "Configured in `config/providers.json`"; describe the JSONL journal; state that `memory.js search` returns exit code 0 when nothing matches. Keep section numbers.

Acceptance (offline tests with a stub provider, no network):
- A repeated identical call returns from cache without calling the provider.
- A malformed answer is not cached, triggers one retry, then moves to the next provider in the role list.
- Journal records carry role, provider, model, tags, outcome.
- A paraphrased query finds an earlier exchange via tags and words.
- Searching an empty memory exits 0.
- `grep -rn "gemini\|groq\|openrouter\|ollama" AGENTS.md prompts/` returns nothing (names live in config and docs only).
- `npm run verify` green; `tools/doctor.js` still compiles `ask.py`.
