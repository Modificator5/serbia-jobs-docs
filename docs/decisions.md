# Журнал решений (ADR)

Формат: дата, решение, почему. Полная история до 2026-10-31: `archive/06-decisions.md`.

---

## 2026-10-28 — Старт проекта

Агрегатор вакансий Сербии + словарь из объявлений для русскоязычных. Площадки
не дают структуры и переводов. Стартовые источники: Infostud, KP, Jooble.

## 2026-10-28 — Короткие карточки, сырой текст не храним

В `jobs.db` только ключевые поля; полное описание нужно лишь для извлечения слов,
затем удаляется. Пост в ТГ компактный, тяжесть — по ссылке.

## 2026-10-28 — Telegram: сначала канал, бот потом

Канал проще, быстрее, витрина растёт сама. Бот с подписками — вторым шагом.

## 2026-10-28 — Фильтр зарубежных вакансий

Вакансии вне Сербии отсекаются в `upsertJob` по контекстным иглам («u Nemačkoj»);
вакансии с немецким языком в Белграде не трогаем.

## 2026-10-28 — Приватный основной репозиторий + публичное зеркало docs

Код и docs — в приватном `origin`; `data/`/`.env` — только локально. Публичное
зеркало `Modificator5/serbia-jobs-docs` нужно внешним ИИ (баг коннектора claude.ai
с приватными репо: anthropics/claude-code #96351, #97723, #68517).
**Обновлено 2026-10-31**: двойной push-URL у `origin` убран; добавлен отдельный
remote `mirror`, пуш — только по явной задаче пользователя.

## 2026-10-28 — Режим выживания (бесплатный период)

Дефолты парсеров снижены, паузы сохранены; ИИ-делегации ≤2 на задачу; тесты —
по CSV-снимку, не по сети. Полное описание: `archive/09-audit-economy.md`.

## 2026-10-28 — Карточка: консенсус двух сетей

Пустые поля — убрать строку (не «н.д.»); сниппет 3 строки; город — первым;
чип категории — справа, для drugo не показывать. Журнал: `logs/ask-journal.md`.

## 2026-10-31 — Конституция AGENTS.md и память с тегами

Решение: единый входной документ `AGENTS.md` (закон для любого ИИ), `CLAUDE.md` —
указатель; память задач `memory/tasks.jsonl` с тегами SOLVED/TRIED/REJECTED/PENDING
+ `tools/memory.js`. Почему: экономия токенов (сначала поиск опыта), единые правила.

## 2026-10-31 — Документы: 7 канонических + архив

`docs/` сведён к `architecture`, `sources`, `decisions`, `operations`, `agents`,
`onboarding`, `progress` + `README.md` (индекс); прежние нумерованные и howto-*
файлы — в `docs/archive/`. Почему: 20+ файлов расходились, дублировали и устарели;
`AGENTS.md` — побеждает при противоречии.

## 2026-10-31 — cleanup по last_seen, не по posted_at

Решение: `tools/cleanup.js` удаляет вакансии, не встречавшиеся в листингах дольше
30 дней (`substr(parsed_at,1,10) < cutoff`). `posted_at` больше не критерий.
Почему: старый код удалял активные объявления с давней датой публикации; дата
публиции ≠ актуальность. Дополнительно: даты из будущего (срок действия в
HelloWorld) → NULL через `normalizePostedAt`.

## 2026-10-31 — Кеш ask.py — под фактическим провайдером, модель в ключе

Решение: `save_to_cache` пишет под провайдером, реально ответившим (`p`), а не
запрошенным; ключ кеша = sha256(provider|model|prompt). Почему: старый баг
тихо отдавал ответ одного ИИ из кеша другого.

## 2026-10-31 — Единый пайплайн daily.sh

`npm run runAll` → `tools/daily.sh` (единственный источник истины цикла):
flock от параллельных запусков, пошаговое логирование с временем, ошибки не
глотаются (exit 1 при любом FAIL), шаги: glossary → scrape x4 → translate →
enrich → cleanup → exports → check. Почему: прежний runAll дублировал Infostud,
не запускал cleanup/enrich, viewer блокировал завершение.

## 2026-10-31 — Единая система инструкций воркеров

Решение: базовый `prompts/worker-core.md` + ролевые `worker-logic.md` (STATUS/FACTS),
`worker-coder.md` (сырой код), `worker-routine.md` (конверт `{"status":"success","data":...}`);
`prompts/lead-engineer.md` — протокол оркестратора (4 блока для пользователя,
нулевая вежливость к воркерам, повтор один раз при нарушении формата).
`tools/ai.js:normalizeWorkerJson` принимает конверт или сырой JSON.
Почему: прежний `worker-analyst.md` требовал «First word Yes/No» и противоречил
JSON-задачам (обходили текстовым override в промпте) — источник хрупких ошибок.
`SYSTEM.md` сведён к указателю на `AGENTS.md` (единый закон).

## 2026-10-31 — CI и офлайн-тесты парсеров

Решение: `.github/workflows/verify.yml` (Node 22, `npm run verify`);
`tests/parsers.test.js` — фикстуры для 4 парсеров без сети; `check`/`doctor`
в CI пропускают отсутствующие локальные БД/артефакты как warning.
Почему: проверка должна быть воспроизводимой без секретов и живой сети.

## 2026-10-31 — Telegram-публикатор

Решение: `tools/publish-telegram.js` — карточка по канону, `is_published`,
dry-run без токена, `retry_after` при 429; автоматической публикации в `daily.sh`
нет (только явная команда). Почему: канал — первичная витрина, но авто-постинг
без контроля опасен (дубли, брак).

## 2026-10-31 — Фильтр зарубежных вакансий по полю city

Решение: к контекстным иглам добавлен список стран/регионов, сверяемый только с
`city` («Kipar - Svi gradovi», «Nemačka»). Почему: площадки пишут страну без
предлога; прежние иглы такие вакансии пропускали.

## 2026-10-31 — GitHub Pages не авто-деплоится

Решение: `jobs.json` остаётся локальным; статическая витрина не обновляется
автоматически, основной канал — Telegram. Для Pages нужен отдельный деплой
(ветка/CI с БД). Почему: противоречие «jobs.json исключён из git, но Pages из git»;
не плодим преждевременную инфраструктуру.

## 2026-10-31 — Новые источники: только разведка

Решение: poslovi.rs / oglasi.rs / lakodoposla — статус research, без парсеров.
Причины: poslovi.rs отдаёт в листинге «Rok za apliciranje» (срок подачи, не дата
публикации) и зарубежные вакансии (Kipar); robots oglasi.rs/lakodoposla запрещают
query-фильтры. Нужна отдельная проверка пагинации и качества до реализации.

## 2026-10-31 — Публикатор: ревью двух воркеров и переписывание

Решение: по итогам ревью Gemini + Groq (fallback) исправлены: URL с токеном строился
до чтения `.env` (критично: реальная отправка шла с пустым токеном); `--dry`
парсился как лимит; при 429 терялась текущая карточка; `disable_web_page_preview`
заменён на `link_preview_options`. Добавлены: lock `logs/.publish.lock` (нет двойной
публикации), `getMe`-preflight, лог `logs/publish-*.log`, безопасная обрезка с
сохранением ссылки, офлайн-тесты `tests/publish.test.js`. Канал:
`@DecentralizedCapitals` (бот `@HybridIntBot`, админ).

## 2026-10-31 — Зеркало docs сохраняется, синхронизация вручную

Решение: `mirror` не удаляем (нужно для чтения внешними ИИ через raw), но
синхронизация только явной командой `git push mirror main docs`, без авто-пуша.
Почему: зеркало отставало на несколько коммитов и работало непрозрачно; ручной
пуш делает состояние предсказуемым.

## 2026-11-03 — Очистка защищена от «мёртвого» парсера и массового удаления

Решение: `cleanup` никогда не удаляет строки источника, у которого нет ни одного
показа внутри окна хранения, и отказывается работать, если под удаление попадает
больше 50% всех вакансий, без `--force`. Причина: сломанный парсер выглядит так же,
как «все вакансии устарели», а удаление необратимо.

## 2026-11-03 — Проверенная резервная копия перед дневным циклом

Решение: `tools/backup-db.js` (`VACUUM INTO` + `integrity_check`, хранение
`keep` новейших копий) выполняется первым шагом `daily.sh`, а `cleanup` запускается
только при успешном бэкапе и всех парсерах. Причина: в базе лежит кеш переводов
(`professions`), восстановление которого стоит токенов.
